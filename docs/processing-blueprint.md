# Relay 加工蓝图

## 文章、工作区与会话

- **一篇文章对应一个长期工作区。** 用稳定的文章 ID 定位工作区，原文和加工稿遵循[内容契约](../reading-lab/docs/content-format.md)。
- **一轮加工对应一个 Pi 会话。** 会话从共享的、经过验证的 checkpoint 开出独立分支，再接收本篇任务。同一篇文章同时只有一个会话写稿。重跑沿用文章工作区，可以另开会话。
- **任务结束后释放运行资源，保留 Pi 原始会话记录。** 记录留作未来问答的材料，当前直接保存。

## 固定启动目录与共享素材

Pi 的项目目录在训练、模拟和实际加工中保持一致。文章工作区各有稳定路径，由启动器为每轮任务绑定。会话内 `relay config` 显示项目目录，Agent 通过 Relay CLI 的默认目标读写当前文章。

共享 checkpoint 保存通用工作方式和精选示例。实际任务的文章 ID、工作区路径、原文及工具返回值随任务分支接在共享前缀之后。训练会话中的篇目可以作为明确标注的示例保留。缓存命中以供应商返回的用量为准。[DeepSeek 缓存规则](https://api-docs.deepseek.com/zh-cn/guides/kv_cache/)

Agent 写当前文章的稿件，可以按需读取其他文章和共享素材。跨文参考保留来源指向。周报也可以有自己的文章工作区，读取多篇稿件作为素材。

### 当前目录布局

本地 `relay pi` 从 `processing/` 启动，案例位于 `content/<article-id>/`。仓库中的 `reading-lab` 链接保留已安装的 Relay 命令、旧工作区路径和 Practicum 现有镜像构建入口。[CLI 启动说明](../reading-lab/docs/cli.md#启动-pi)

生产 Practicum 岗位使用冻结配置里的 `/work/relay/reading-lab`，将当前文章挂载到 `/work/article`。[Practicum 配置](../reading-lab/practicum.json) · [生产发布](../reading/docs/production.md)

## 后续计划

1. **按职责重排 `infos/`（本地已实施）。** 采集交付带来源和产品归属的正式更新，加工交付通过校验的文章，阅读负责查找和浏览文章。定时派稿与上线属于部署编排。先定跨模块交接和依赖，再移动目录。
2. **定义通用的 Agent 工作环境。** 训练、验收和生产使用同一套容器路径、Relay CLI 入口和启动配置。工作区布局与测试配置见[Relay Agent 工位](../processing/runtime/README.md)。宿主机路径由启动器映射，仓库改名或重排时更新映射即可。
3. **保留文章工作区与已加工文章的访问能力。** 本轮文章按稳定 ID 持久化，Agent 可读写本轮稿件。其他已加工文章通过只读入口按需查阅，引用时保留来源。先验证按 ID 读取能够支持关联报道，资料筛选与索引等有需要再定。
4. **确认布局和访问边界后重新训练。** 先验证 Relay CLI 能读写本轮文章、读取既有稿件并通过校验，再按[Pi 培训与上岗](../reading-lab/docs/pi-training.md)跑真实文章闭环。以阅读页审稿、工作区检查和缓存用量作为验收依据，通过后冻结新 checkpoint 并切换生产岗位。

## 编辑部对应关系

**编辑部** · Pi 固定启动目录<br>
├─ **编辑交接本** · 共享 checkpoint，派稿时从同一版开新会话<br>
├─ **每篇稿件的档案袋** · 文章工作区，放原文和加工稿<br>
├─ **资料柜** · 其他文章与共享素材，按需查阅<br>
└─ **本次编辑记录** · Pi 会话，交稿后原样归档
