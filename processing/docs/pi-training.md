# Pi 培训与上岗

Practicum 训练、验收和派工使用 [Relay 配置](../practicum.json)。模型固定为 `deepseek/deepseek-flash:high`。

| 阶段 | 本轮任务 | 验收 |
| --- | --- | --- |
| 1. 对齐 | 给项目目标、Relay CLI 入口和加工顺序。 | Pi 能说清读者要获得什么，以及稿件如何提交。 |
| 2. 读案例 | 读已有试验的成稿、读者反馈和改稿。 | Pi 能指出读者在哪里卡住，改动补上了什么。 |
| 3. 对齐表达原则 | 结合案例给出 Relay 已沉淀的写作风格。 | Pi 能说明正文、图和原文依据各承担什么。 |
| 4. 全文练习 | 用一篇真实文章写全文简要、解读，通过 CLI 提交。这轮到此停下。 | 检查两个视图的分工、表达效果和提交结果。 |
| 5. 章节练习 | 为同一篇文章的各章节写简要、解读。 | 点开任意一节，读者能独立进入场景。 |
| 6. 串读练习 | 分别串读各章简要和解读，发现断点时局部修改。 | 章节能接着读，改动保留原文事实。 |
| 7. 全流程测试 | 给另一篇未用于本轮引导的真实文章，由 Pi 独立跑完全文、章节、串读、修订和校验。 | 人在阅读页验收稿件，必要时对照原文与修改。 |
| 8. 反馈与上岗判断 | 记录具体的阅读卡点和事实问题。发现问题时，改后再验。 | 由人确认是否上岗。 |
| 9. 上岗 | 发出通用上岗指令，记录通过验收的会话和冻结位置。 | 共享起点把本轮文章标成练习，以后从新任务取得当前文章。 |

训练材料依次用[项目手册](../../docs/product-handbook.md)、[CLI 说明](cli.md)、[可理解性案例](comprehension-cases.md)和[写作风格](content-style.md)。测试原文在第 7 阶段发给 Pi，读者反馈和上岗决定放在交稿后。
