# 稿件可理解性验收

以下为虚构示例。练习稿见 [Relay 示例](../cases/relay-demo/README.md)。

| 读者卡点 | 达标表现 | 验收题 |
| --- | --- | --- |
| 「设计第二版」开头突然出现。 | 先说团队要解决什么，以及第一版为什么不够用。 | 只读首段，能说出上一版的结果和下一步的目的吗？ |
| 「除专项指南外还要读项目手册」交代了过渡，分工仍不清楚。 | 用同一个任务说明哪个文档管特定操作，哪个文档管全仓约定。 | 新同事改文档和做数据库迁移分别会查什么？ |
| 每个功能名都列出来了，读者不知道何时用得上。 | 从一次具体操作起句。例如你把写到一半的编辑器关掉，回来时草稿仍在。 | 能说清场景、发生的变化和触发条件吗？ |
| 图里列了三个词，读者看不出它们的关系。 | 图呈现先后、分支或对照，正文交代场景和条件。 | 扫图能说出结构；读正文能解释为什么吗？ |
| 小改稿后扩大了事实范围。 | 对照原文核实对象、条件和时间。 | 「可恢复最近一次保存的草稿」有没有被改写成「任何草稿都能恢复」？ |

阅读规则见 [写作风格](content-style.md)。
